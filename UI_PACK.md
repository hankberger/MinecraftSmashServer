# Vanilla fighter menu

The Play compass, spawn podium and `/smash join` open a vertically centered portrait menu with a live fighter to its right in Heartwood Pavilion. The mode row reads **1v1 / 4 Player / Practice**, with **1v1 selected for a fresh session**. Parties larger than two default to 4 Player. Five fighters ship now; each page fits six portraits, three per row, with page arrows when needed. Portrait tiles are 54 pixels square, 50% larger than the previous grid, with larger faces and names. The party roster is attached directly to the menu's left, showing the leader and each member's ready state. Full 16-character usernames wrap onto two lines when necessary. Manage parties through the lobby's Party hotbar item or `/smash party`.

Search stays on the same stage with a highlighted **In Queue** panel, elapsed time and animated searching dots, then transfers directly into a match. The timer is time already spent waiting, not an estimate or fake completion percentage. Changing a fighter or cancelling search does not return players to the lobby. Back to lobby and Escape cancel the selection session; winner Results and Change fighter still connect to the same picker.

## Delivery

Players accept Minecraft's ordinary server-resource-pack prompt. The pack is required for this UI and cached by SHA-1. It contains about 200 KiB of bitmap fonts, portraits and menu presentation assets, including a narrow GUI background filter. No client mod is required. No Fabric installation or manual copying is needed on clients. Reconnect after a failed download to retry.

`UiPack` offers the pack after lobby arrival settles and selection waits for a successful-load response. The network lobby defaults to `https://raw.githubusercontent.com/hankberger/MinecraftSmashServer/main/resourcepacks/<sha1>.zip`. Push pack and server changes together; CI validates that the public artifact, bundled artifact and font index match. Retain published hash files for older servers and rollback deployments. An object store/CDN may replace GitHub through `SMASH_RESOURCE_PACK_URL`; the downloaded bytes must match the bundled pack. Never overwrite a hash URL.

Standalone `PLAY.cmd` serves the bundled zip on an ephemeral localhost HTTP port. Remote standalone hosting needs a publicly reachable `SMASH_RESOURCE_PACK_URL`. Docker Compose passes that optional override to the lobby. Arenas do not show menus or send additional packs; returning lobby connections re-confirm the cached pack. `SMASH_RESOURCE_PACK=disabled` retains the old in-world selection flow for emergency fallback.

## Native rendering and input

The picker uses a native six-row container for centered positioning and mouse regions. Custom bitmap artwork in its title paints the 176-by-222 GUI-pixel panel; a 64-pixel party panel sits four pixels to its left. Chest textures and hover highlights are transparent. Portraits cover nine empty slots each; mode and footer buttons each cover three slots. Invisible, tooltip-free input items suppress the first-person hand. No visible inventory items serve as buttons. Bitmap glyphs reserve Minecraft's one-pixel advance so artwork and hit regions agree. Native centering recalculates on resize, including fullscreen changes, and keeps the panel vertically aligned with the live stage.

The packed stage teleports the player to the final view and sends a private camera's spawn, metadata and attachment together before opening the menu. Both eyes share the same position. There is no timed camera handoff or periodic reattachment, which previously shifted the stage about 750 ms after arrival. The private camera is removed when selection ends. A slightly closer view enlarges the preview while keeping it to the right of the menu.

Picker mouse clicks use native container packets. Only left/right pickup clicks on known regions with the current container ID and content revision can act; all inventory mutations and shortcuts are intercepted. Party dialogs still use vanilla `minecraft:custom` actions. Both routes run on the server thread with the same player-bound action/debounce checks. Neither runs hidden chat commands, so rapid browsing does not consume Minecraft's command-spam budget. Normal chat and command protection stays intact.

Selection tokens and content revisions rotate when interactive state changes. Timer and dot animation redraws retain both, so they cannot invalidate a click in flight. Stale, guessed and other players' tokens cannot act. Escape and the Back button cancel independently of selection debounce. Empty-space clicks do nothing. Redraws reuse the same server container, preserving selection and queue state.

The pack makes the in-world menu background texture transparent and gives Minecraft's menu-blur post effect an empty pass list. The GUI shader removes the native fullscreen C0101010-to-D0101010 dimming gradient, matching both its color and full-screen dimensions. It retains the older picker focus-edge filter for compatibility. Ordinary control rectangles, text and world shaders retain vanilla rendering. These overrides also affect other native menus using those assets while this server pack is active; vanilla provides no per-screen identity to the shader. Generic chest textures, slot highlights and the translated Inventory label are also suppressed by this server pack.

GUI scale and FOV remain local Minecraft settings that the server cannot read or enforce. **GUI Scale: Auto** is recommended for fullscreen, and new local PLAY profiles now default to Auto; existing preferences are preserved. Centering is automatic at every scale, but a fixed low scale deliberately keeps native UI small on larger displays. Vanilla fixes the mouse regions to the centered container: arbitrary CSS-like percentage positioning/scaling would separate the artwork from the click targets. Checks cover Minecraft 26.2, 1280x720 and 1024x768 at scales 2/3, and 1920x1080 at scale 2 and Auto, first-person perspective and roughly 70 FOV. Extremely wide/narrow windows and unusual FOV settings can change the model's relation to the menu. The pack covers formats 88.0–97.1. A `v26_3` overlay supplies 26.3 GUI shaders with its reordered uniform block and explicit interface locations; 26.2 continues using the original shaders. Both use the same portrait artwork and click regions. Labels are currently English; bitmap portraits do not provide full narrator accessibility. Skin browsing and drag-to-rotate remain future work.

Results use the left five columns of the six-row canvas beside the winning model, with portraits, KOs, damage dealt, the player's points reward and balance, and Rematch, Play again, Change fighter and Lobby buttons. The fighter picker's party sidebar also shows the account balance. These labels are informational and add no mouse targets. Only available party actions appear. The three inventory rows and hotbar provide mouse targets; scoreboard clicks, transparent space to the right and inventory shortcuts are inert. Actions require the current container ID and content revision, and votes redraw that same container. Escape returns to the lobby. A native button dialog is the fallback when the pack is unavailable.

## Assets and checks

Run `C:/Python312/python.exe tools/build_ui_pack.py` with Pillow and the official 26.2 client cached in the sibling Gradle directory. It derives text and portraits from vanilla assets and writes `src/main/resources/ui/{pack.zip,index.json}` plus `resourcepacks/<sha1>.zip`. Commit all three. Remove unpublished intermediate packs; retain published ones.

`python -m unittest discover -s deploy -p 'test_*.py'` checks artifact/hash consistency and every portrait strip. `gradlew runClientGameTest -PdedicatedTests -PpackedTests` exercises a genuine pack prompt and HTTP download, mouse selection, all four portrait corners, stale/forged actions and container revisions, blocked inventory shortcuts, party invites, ready/cancel/change, Escape, remembered selection, practice, winner controls and several window/UI sizes. It also checks replacement of persisted stage geometry, a steady camera from the first visible menu frame, focus pixels at multiple GUI scales, sidebar cleanup, elapsed queue updates and action validity across animation frames. The spam regression bursts 60 native mouse clicks as a non-op, checks that picker and party buttons leave the command-spam counter untouched, rejects malformed custom actions, and confirms actual command spam still disconnects the client. Latest logs are under ignored `evidence/large-picker-native.log`.

`deploy/matchmaking_smoke.py` checks stock clients across the real proxy and containers; see NETWORK.md.

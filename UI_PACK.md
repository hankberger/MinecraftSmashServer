# Vanilla fighter menu

The Play compass, spawn podium and `/smash join` open the wide portrait menu over Heartwood Pavilion, with a live fighter on the right. The mode row reads **1v1 / 4 Player / Practice**, with **1v1 selected for a fresh session**. Parties larger than two default to 4 Player. All eight fighters appear on one page in a four-column, two-row grid of 54-pixel portraits. The party column to the left shows each member's username and current fighter portrait, a leader crown, ready checks and a ready count. Credits and Store are grouped in their own card below the party. Portraits update while teammates browse, before ready-up; changing your choice clears only your own ready vote. Full 16-character usernames wrap onto two lines when necessary. The party header, member chips and **+ Invite friends** open the larger social panel. An invitation count appears on the header. The lobby's Party hotbar item and `/smash party` remain available.

Search stays on the same stage with a highlighted **In Queue** panel, elapsed time and animated searching dots, then transfers directly into a match. The timer is time already spent waiting, not an estimate or fake completion percentage. Changing a fighter or cancelling search does not return players to the lobby. Back to lobby and Escape cancel the selection session; winner Results and Change fighter still connect to the same picker.

## Delivery

Players accept Minecraft's ordinary server-resource-pack prompt. The pack is required for this UI and cached by SHA-1. It contains about 8.5 MB of bitmap fonts, BrawlParty artwork, menu presentation assets and music, including a narrow GUI background filter. No client mod is required. No Fabric installation or manual copying is needed on clients. Reconnect after a failed download to retry.

`UiPack` offers the pack after lobby arrival settles and selection waits for a successful-load response. The network lobby defaults to `https://raw.githubusercontent.com/hankberger/MinecraftSmashServer/main/resourcepacks/<sha1>.zip`. Push pack and server changes together; CI validates that the public artifact, bundled artifact and font index match. Retain published hash files for older servers and rollback deployments. An object store/CDN may replace GitHub through `SMASH_RESOURCE_PACK_URL`; the downloaded bytes must match the bundled pack. Never overwrite a hash URL.

Standalone `PLAY.cmd` serves the bundled zip on an ephemeral localhost HTTP port. Remote standalone hosting needs a publicly reachable `SMASH_RESOURCE_PACK_URL`. Docker Compose passes that optional override to the lobby. Arenas do not show menus or send additional packs; returning lobby connections re-confirm the cached pack. `SMASH_RESOURCE_PACK=disabled` retains the old in-world selection flow for emergency fallback.

## Native rendering and input

### Combat inventory key

The inventory key is disabled while a battle camera is attached, including countdown, practice, sandbox and arena arrival. Each private camera rig also owns an invisible client-only llama behind the camera. Vanilla's custom-vehicle inventory branch sends the key press to the server instead of constructing `InventoryScreen`; `InputPacketsMixin` rejects that request in combat. The server player is never actually mounted, and the llama has no jump control. Movement, jumping, shielding and charge/release continue through the existing input packets. Closing the rig removes the seat and restores ordinary lobby inventory behavior. This works without the resource pack and does not repeatedly close screens, interfere with chat/pause/settings, or replace the camera. `runClientGameTest -PinventoryTests -PdedicatedTests` covers native input and cleanup.

### Queue and battle audio

An accepted Play/Ready or rematch click plays **QueueDrum** once for that player. Actual matchmaking plays **QueueChoir** at 4.5% volume and repeats it while waiting. Merely browsing fighters or waiting for other party members to ready does not start the choir. Cancelling, entering the countdown, leaving or transferring stops the waiting music.

The countdown ends with **FightReverb** and the **FIGHT!** title. After its 601 ms cue, a shuffled **Fight1–Fight5** playlist runs at 42% volume, using every track before reshuffling and avoiding immediate repeats at shuffle boundaries. All fighters and eliminated spectators in a round hear the same sequence. Scheduling uses monotonic elapsed time and the encoded audio durations, so a slow server does not overlap tracks or burst through missed songs. Results immediately stop music and play **GameReverb** once; aborting or leaving a match stops audio without that finish announcement. Practice and sandbox also have battle music.

Choir and soundtracks use Minecraft's **Music** slider; announcements and the drum use **Players**. All nine sounds are stereo Ogg Vorbis so the side camera does not make them fade with distance. The six long tracks stream. The required server pack silences autonomous vanilla background music (not discs or sound effects); vanilla music returns when that pack is removed. Pack-disabled fallback retains the vanilla start/end cues.

`tools/audio_assets/manifest.json` records source filenames, source/encoded hashes and measured durations. Checked-in Ogg files are sufficient for pack builds. To deliberately replace the supplied recordings, run `python tools/import_audio.py <source-folder>` with FFmpeg installed, then `python tools/build_ui_pack.py`. The builder writes the matching server `/ui/audio.json` and content-addressed pack. `deploy.test_ui_pack` checks registration, hashes, stereo headers, timing, streaming flags and the 10 MiB download budget. `MatchAudioTimelineTest` covers scheduling and lifecycle; `runClientGameTest -PaudioTests -PdedicatedTests` verifies actual native playback and stopping through queue, duel, results and practice.

### Account progression

The winner stage owns a private XP card, with a forest/coral backing from `level_ui_assets.py`, native text displays and an interpolated bar. Only committed XP receipts start a count-up. Its animation changes entity metadata, never the container title or cursor state, and all entities share the winner stage's cleanup. Skipping, rematching or reopening results cannot award XP. Without the pack, the same readable native card uses a simple block backing.

The lobby's **Your Level** item and `/smash level` open a 288 × 180 profile card with the current title, progress, next milestone and lifetime XP. Two background glyphs keep the panel within the native font atlas. The level heading uses the existing doubled font; its space advance is accounted for so it does not wrap at the canvas edge. The return button uses the same shadow-free native styling as Party. No client mod or extra resource-pack download is required beyond the updated shared pack.

### Rankings

The rear-right lobby podium and `/smash rankings` open a 384-by-252 GUI-pixel forest panel over the current lobby view. Weekly wins is the default, with underlined tabs for All-time wins and KOs. Ten rows display competition rank, fighter portrait, full username and score; gold/silver/bronze highlight the leading ranks. A separate personal row stays visible outside the top ten and shows Unranked until the player has a score. Back to lobby and Escape close the screen without opening fighter selection or changing matchmaking. Native custom actions retain the cursor when switching tabs and reject stale tokens. Queries run off the Minecraft thread, refresh at most every ten seconds, and cannot reopen a screen after it closes. Pack-disabled servers receive a plain native dialog fallback. `-PrankingsTests` verifies actual resource-pack rendering at GUI scales 2/3, native mouse clicks, stale actions, empty/populated views and return navigation.

### Party and friend finder

Party opens a 392-by-234 GUI-pixel canvas with a full-name roster on the left and **Search / Recent / Invites** on the right. Members show their chosen fighter, leader crown and ready status; the leader can click a member's row to promote or remove them. Empty slots open search. Sending the first invitation creates the party automatically. Search accepts a full or partial Minecraft username, ranks exact and prefix matches first, and paginates three results per page instead of listing the whole server. Invite, Sent, Busy and Offline states are explicit. Incoming invitations offer Join and Decline and expire after two minutes.

The proxy directory includes online players on the shared lobby and arena backends. Players in matches are visible but cannot be invited until they return to the lobby. Local selections supply the live fighter portrait. Recent retains the last 24 teammates/opponents per player in a bounded, in-memory history; it resets on lobby restart. Other players moving around the network do not redraw the panel unless its visible results change.

The vanilla text input cannot be positioned inside an arbitrary bitmap panel. Clicking the search field opens a focused native username form with branded Search/Cancel buttons, then returns to the results. This temporarily replaces the roster panel; the same lobby view or existing fighter stage remains behind it. Opening/browsing/closing Party and sending invites preserve readiness. Joining, leaving or changing the roster resets readiness. Queued parties cannot invite/join; leaving or removing a member cancels the whole group's queue before changing it. Back to fighters uses the native footer and preserves the cursor. When entered from Play, the preview shifts slightly right while Party is open and returns to its original position on exit.

The footer remembers where Party was first opened: entering from the lobby through the Party podium, `/smash party`, or the hotbar head shows **Back to lobby**, while entering from fighter select shows **Back to fighters**. Searching, switching tabs, and reopening the party command preserve that destination. Lobby entry opens directly over the courtyard, like Store: no preview stage, teleport, camera change, or hotbar replacement. Back/Escape simply closes the panel in the same spot. Fighter-select entry retains its existing stage and returns to that same picker. Search, invitations and roster management work in either location, and replacing Party with another lobby dialog releases its refresh loop. Native button labels use the same shadow-free bitmap lettering as their backing artwork, avoiding overlapping dark text/shadows on the coral Search button. Client checks cover both entry routes, Search/Cancel, Escape, and Search text pixels at GUI scales 2 and 3.

`gradlew runClientGameTest -PdedicatedTests -PpartyTests` verifies the real pack, mouse hit regions, username entry, invitation sending/acceptance, member removal, unchanged readiness during browsing, cursor position, stale/foreign token rejection, outgoing expiry, disconnect refresh, creating/joining parties without leaving the courtyard, unchanged position/camera/hotbar from lobby entry, and return to the same fighter stage. Unit checks exercise lookup among 500 players and party authority/capacity rules. Evidence lives in ignored `evidence/party-ui/`. The large panel follows Minecraft's GUI scale; unusually narrow windows can require a lower GUI Scale setting.

The default picker uses a native dialog with a 316-by-171 GUI-pixel canvas. Nineteen native text rows provide mouse targets over the artwork: each 54-pixel portrait spans six rows, and continuation rows retain the same action. The party column is 80 pixels wide, separated from the 228-pixel fighter grid by eight pixels. Skin, mode and primary actions sit beneath the grid. The three mode buttons are 27 pixels tall, with centered labels and clickable continuation rows; Play and the wallet footer sit below them. Bitmap glyphs reserve Minecraft's one-pixel advance so artwork and hit regions agree. No visible inventory items serve as buttons. Invisible input items suppress the first-person hand.

The packed stage teleports the player to the final view and sends a private camera's spawn, metadata and attachment together before opening the menu. Both eyes share the same position. There is no timed camera handoff or periodic reattachment, which previously shifted the stage about 750 ms after arrival. The private camera is removed when selection ends. A slightly closer view enlarges the preview while keeping it to the right of the menu.

Picker and party clicks use vanilla `minecraft:custom` actions with player-bound tokens and debounce checks on the server thread. The optional compact picker uses native container packets and also validates container ID, content revision and click type; inventory mutations and shortcuts are intercepted. Neither route runs hidden chat commands, so browsing does not consume Minecraft's command-spam budget. Normal chat and command protection stays intact.

Selection tokens rotate when interactive state changes. Timer and dot animation redraws retain tokens, so they cannot invalidate a click in flight. Stale, guessed and other players' tokens cannot act. Escape and the Back button cancel independently of selection debounce. Empty-space clicks do nothing. Redraws preserve the same stage, selection and queue state.

Dialog-to-dialog navigation preserves the cursor: Store, party pages and skin confirmations replace the current screen directly, with `after_action: none`. A handoff invalidates the old actions without sending a close packet. Only the owner of an open menu can clear it, so ready-up cleanup cannot briefly close the fighter picker. Secondary actions are consumed before execution; if no replacement or explicit close occurs, the consumed screen is closed on the server. Minecraft's Escape handling always uses its native close path, so Escape may still center the mouse when a return screen opens; clicking the on-screen Back/Close buttons avoids that path.

The pack makes the in-world menu background texture transparent and gives Minecraft's menu-blur post effect an empty pass list. The GUI shader removes the native fullscreen C0101010-to-D0101010 dimming gradient, matching both its color and full-screen dimensions. It retains the older picker focus-edge filter for compatibility. Ordinary control rectangles, text and world shaders retain vanilla rendering. These overrides also affect other native menus using those assets while this server pack is active; vanilla provides no per-screen identity to the shader. Generic chest textures, slot highlights and the translated Inventory label are also suppressed by this server pack.

GUI scale and FOV remain local Minecraft settings that the server cannot read or enforce. A fixed low GUI scale keeps the menu smaller on larger displays; Auto can make it overlap the stage. Existing local PLAY preferences are preserved. The wider dialog is horizontally centered by Minecraft, but its vertical position is fixed by the native dialog layout rather than aligned to the fighter. Checks cover Minecraft 26.2 at 1280×720, 2560×1440 (scale 2 and Auto), and 960×720 (scale 3), first-person perspective and roughly 70 FOV. Unusual aspect ratios and FOV settings can change the model's relation to the menu. The pack covers formats 88.0–97.1. A `v26_3` overlay supplies 26.3 GUI shaders with its reordered uniform block and explicit interface locations; 26.2 continues using the original shaders. Both use the same portrait artwork and click regions. Labels are currently English; bitmap portraits do not provide full narrator accessibility. Skin arrows above the mode row preview outfits on the stage, with Equip or Unlock on that same row. Locked skins show a shortfall or an affordable unlock price; purchases require confirmation. Play with the equipped outfit remains available while previewing another skin. The separate wallet opens the branded Store; Close and Escape return to the same stage and preview. Checkout setup is documented in POINTS.md. Queuing replaces these controls with queue progress. Drag-to-rotate remains future work.

Results use the left five columns of the six-row canvas beside the winning model, with portraits, KOs, damage dealt, the player's points reward and balance, and Rematch, Play again, Change fighter and Lobby buttons. The fighter picker's separate wallet shows the account balance. These labels are informational and add no mouse targets. Only available party actions appear. The three inventory rows and hotbar provide mouse targets; scoreboard clicks, transparent space to the right and inventory shortcuts are inert. Actions require the current container ID and content revision, and votes redraw that same container. Escape returns to the lobby. A native button dialog is the fallback when the pack is unavailable.

## Layout and positioning

The wider layout is the default for all Play entry points. `/smash menu compact` selects the former centered inventory layout; `/smash menu wide` restores the default. The choice lasts for the server session and is remembered when reopening Play. Switching keeps the current stage, fighter and queue. Both use the same skin purchases, party actions, ready-up and matchmaking. The compact fallback retains 36-pixel portraits within a 176-by-222 native container; the default's portraits are 50% larger.

Vertical centering is not implemented: vanilla fixes the dialog body near the top at low GUI scales and the menu may overlap the character at Auto. The server cannot detect the viewport or enforce GUI scale. Shader-only repositioning would separate the artwork from its native mouse targets, while fixed blank padding would cause scrolling on smaller windows. Minecraft's dialog title, security warning and Back to lobby footer remain visible. The wider menu is the adopted approach despite this positioning constraint.

`gradlew runClientGameTest -PdedicatedTests -PwidePickerTests` checks the default `/smash join` flow, actual mouse selection for every fighter and portrait corners, all three vertical portions of each mode button, Store return, queue/cancel, switching layouts without leaving the stage/queue, Escape and reopening. `-PcosmeticsTests` exercises purchases and equipped-skin transfers through the default picker. Screenshots under ignored `evidence/picker-large/` show 1280×720, 2560×1440 at scale 2 and Auto, and 960×720 at scale 3.
